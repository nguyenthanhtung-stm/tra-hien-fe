# Trà Hiên V2

Spec-first rebuild of **Trà Hiên**. This repository is independent from prior implementations.

> **State:** V2 specifications are stored in `docs/spec/`. Architecture and implementation should follow spec audit and explicit decision gates. There is no automatic repo-structure CI blocking specification updates.

## Getting started

This repository is **frontend only**. For running Store/Admin against the separate backend, see [infra/README.md](infra/README.md).

1. Clone: `git clone https://github.com/jimthanhnobi/tra-hien.git`
2. Add or replace your authoritative Markdown specs under `docs/spec/` and preserve filenames, hierarchy, and links. Commit/push to `main` or use a separate documentation branch and PR as you prefer. No repository-guard script or Actions workflow is required to push specs.
3. Open Codex at the repository root. Run `$spec-audit` after any substantial spec change; review conflicts and decisions before coding.
4. Run `$architecture-plan` to produce a reviewable architecture and phased delivery plan once blocking questions are resolved.
5. Implement small vertical slices using `$implementation-slice` and run `$review-gate` before merging code.

**Don't build the app until the specification audit and architecture decision are reviewed.**

## Repository map

- `AGENTS.md`: repo-wide Codex operating rules and safety gates
- `docs/spec/`: authoritative user-provided requirements (not generated by AI)
- `docs/analysis/`: generated spec inventory, gap analysis, traceability
- `docs/architecture/`: architecture proposals and decisions
- `docs/plans/`: phased implementation plans and tasks
- `docs/reviews/`: review findings and proof of verification
- `.agents/skills/`: Trà Hiên-specific Codex skills
- `.github/`: optional PR/issue templates (no repository-guard Actions job)

## External tooling

Evaluate [GitHub Spec Kit](https://github.com/github/spec-kit) for optional spec-driven planning and [Superpowers](https://github.com/obra/superpowers) for systematic implementation/testing. Install externally in your Codex environment **after reviewing** their source and compatibility. They are not vendored into this repo.

## Non-negotiable quality rules

- Spec is the authority. When unspecified, mark `OPEN`; do not invent requirements.
- Every implementation task must cite its specification sections and acceptance criteria.
- Never silently change application architecture or database schema.
- No fabricated test results. Record exact commands and outcomes in PRs.
- Prefer small PRs and independent review. Never claim that AI review replaces tests.
- Keep secrets, customer PII, credentials, and production data out of git.

See [docs/WORKFLOW.md](docs/WORKFLOW.md) for exact operating steps.

## Repo này chỉ chứa Frontend

Repo gồm `apps/store`, `apps/admin` (Next.js) và `packages/api-client`. **Backend (.NET API +
PostgreSQL + migration) nằm ở repo riêng**; chạy BE trước theo README của repo đó

## CI và sinh hợp đồng API

CI chạy trên PR vào `main` và push `main`. Hai status check: `Frontend verification`,
`Docker regression builds`. Từ root, dùng Node 22.22.2 và pnpm trong `packageManager`:

```powershell
corepack pnpm install --frozen-lockfile
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
```

Khi BE đổi API, với BE đang chạy:

```powershell
corepack pnpm generate:api   # đọc OPENAPI_URL, mặc định http://localhost:8080/openapi/v1.json
corepack pnpm check:api      # báo lỗi nếu openapi.json/schema.ts đã commit lệch với BE
```

Có thể dùng file đã lưu thay vì BE đang chạy: `$env:OPENAPI_FILE = "duong/dan/openapi.json"`.
Commit cả `packages/api-client/openapi.json` và `src/generated/schema.ts` khi API đổi;
không ghi đè `src/index.ts`.
